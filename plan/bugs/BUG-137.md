# BUG-137: Terminal の起動で、窓の本体の数秒後にタイトルバーが出る

Reproduction: reproduced（ユーザー、5330 実機。3 回目ぐらいの起動から出なくなった）
Disposition: scheduled（[ws099-p023](../ws099/phase023/phase.md)）
Discovery: 2026-10-02 user（5330 実機試験の後）「ターミナルアプリを起動したとき、先にウィンドウ本体が表示され、数秒遅れてからウィンドウタイトルバーが表示されました。…私としてはバグとしますので記録して修正してください。なお、3回目くらいのアプリ起動で生じなくなりました。」
Note: 初回だけの遅れ（cache・font・icon の読み込み、BUG-135 の stat の遅さの可能性）を疑う。非機能の bug だが修正する（ユーザー）。

## 原因と直し（2026-10-02 ws099-p023 / q609-i01、P2、QEMU）

原因: Terminal は keiland_titlebar を、窓・renderer・menu を開いた後に作っていた。zdesktop は SSD の configure を送るが、Terminal はその configure を acknowledge する前に最初の画像を commit する。このためその commit は CSD（`ZWL DECORATION applied mode=1`）で map され、SSD は acknowledge の後の次の commit で初めて効く。Terminal は画面が変わるまで commit しないので、タイトルバーは「次に描く時」まで出ない。QEMU では 5.5 秒たっても出なかった（[log](../ws099/phase023/evidence/base-terminal-zdesktop.log)、[PNG](../ws099/phase023/evidence/base-terminal-5s.png)）。何回目の起動で出るかは、ack と最初の commit のどちらが先になるかの競争による。
直し: `terminal_window_open`（`userland/desktop/terminal/window.c`）の中で、registry の roundtrip の前に titlebar を作る。roundtrip の間に SSD の configure が acknowledge されるので、最初の画像が SSD で map される。直した後は 3 回の起動の全てで `DECORATION applied mode=2` が `MAP` より先に来て、本体とタイトルバーが同じ画面に出た（[PNG](../ws099/phase023/evidence/fix-terminal-first.png)）。
BUG-135 との関係: 遅れを決めるのは stat ではなく、ack と commit の順だった。実機（5330）での確認は未実施。

2026-10-03 Q1: ws099-p023 で原因と修正を QEMU で確認（main d5e5cfa6a）。Disposition は 5330 のユーザーの目視の後に resolved にする。
