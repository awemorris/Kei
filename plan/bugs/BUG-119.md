# BUG-119: greeter の Shut Down の後、QEMU が終わらない（電源が切れていない恐れ）、画面は greeter のまま

Bug ID: `BUG-119`
Reproduction: reproduced（QEMU の Venus、ws099-p004、2026-09-30）
Disposition: tracking（reopened 2026-10-03: S1 の実機（素の 5330）で greeter の Shut Down の後、画面は消えたが電源が切れなかった。QEMU の S5 の確認では足りない。実機が要る）
Date: 2026-09-30
Source: ws099-p004 のサブエージェントの報告
Owner: WS099（compositor・sessiond）、電源の経路なら kernel（ACPI）

## 観測

greeter の Shut Down を押すと、40 秒で guest は SSH に応じなくなる（落ちた）が、QEMU の process は終わらない。画面は greeter の絵のまま止まり、
電源を切っている途中だと分かる表示は無い。実機（5330）でどう見えるか、電源が切れるかは未確認。

## 次にすること

- ACPI の電源断（S5、`\_S5` と PM1a_CNT の SLP_EN）まで届いているかを QEMU の monitor で確かめる。届いていれば QEMU は終わるはず。
- 電源を切る途中の表示（「Shutting down…」など）を greeter か compositor が出すか。
- デモの台本 S14（Shut Down で電源が切れる）に関わる。

## 2026-09-30 ws099-p008 の確認と案

- QEMU の monitor: `/sbin/poweroff` の後も `VM status: running`、全 CPU が HLT（CPU0 `amd64_lapic_panic_all+0x49`、他 `hal_cpu_park+0x30`）。
  **ACPI の S5 の電源断が kernel に無い**（init は poweroff でも `KERN_SYSTEM_HALT`、UAPI は HALT と REBOOT だけ、pcat の `kern_platform_halt` は
  CPU を止めるだけ、`hal_poweroff()` は宣言だけで x86・amd64 に実装が無い）。
- 直し方の案（HAL の API は変えない）: UAPI に `KERN_SYSTEM_POWEROFF`、`system-device.c`、`kern_platform_poweroff()`、ACPI の
  `drv_acpi_poweroff()`（起動時に `\_S5` を評価して SLP_TYP を覚え、電源断で `\_PTS(5)` と PM1a/b_CNT に SLP_TYP|SLP_EN）、init が POWEROFF を送り
  EOPNOTSUPP なら HALT。詳細は [ws099-p008](../ws099/phase008/phase.md)。
- greeter の「Shutting down…」の表示は ws099-p009。

## 2026-09-30 ws073-p043 の修正（resolved）

- UAPI に `KERN_SYSTEM_POWEROFF`、`/dev/system` の ioctl、`kern_platform_poweroff()`（pcat は `drv_acpi_poweroff()`）、ACPI の driver に S5 の電源断
  （起動時に `\_S5` を読み、電源断で `\_PTS(5)` → PM1a/b_CNT に SLP_TYP|SLP_EN）、init は POWEROFF を送り `EOPNOTSUPP` なら HALT。
- QEMU（q35、KVM）: `/sbin/poweroff` の 6 秒後に QEMU が終わり、QMP の event は `SHUTDOWN reason=guest-shutdown`（ACPI の S5）。`/sbin/reboot` は
  従来どおり `guest-reset`。greeter の Shut Down の経路（`c1-boot-shutdown.sh`、`C1_REQUIRE_QEMU_EXIT=1`）の結果は [ws073-p043](../ws073/phase043/phase.md)。
- 5330 の実機で電源が切れるかはユーザーの目視（未実施）。実機の FADT が HW_REDUCED で sleep control register が memory 空間なら halt に戻る（log に出る）。

2026-10-03 P2（ws099-p027 の BUG-095 の読みから、S2 の確かめ方の案）: S1 の「画面は消えたが電源が切れない」は、init が要求を受けて services と device を
止め、`drv_acpi_poweroff` が失敗して init が halt に替えた形と読める（init が oneshot に止められていれば greeter の絵が残るはず。[BUG-095](BUG-095.md)）。S2 で:
1. 起動の後、terminal か SSH で `dmesg | grep ACPI`: `ACPI: S5 is SLP_TYP a/b` が出ているか、`no _S5`・`no sleep control register in I/O space; no soft-off`・
   `hardware-reduced platform`・`the platform did not enter ACPI mode` のどれかが出ているか（soft-off の準備の可否）。
2. Shut Down の前に `service list`: `ntpdate`・`networking` が starting のまま（oneshot が init を止めている）でないか。
3. greeter を通さず terminal から `/sbin/poweroff` を 1 度: 同じく画面が消えて電源が残るなら、greeter・sessiond の経路ではなく kernel の S5。
   その時、画面に kernel の文字の console が見えれば `ACPI: the platform did not turn off`・`system: the power-off failed (error N)`・
   `init: the machine cannot turn its power off; halting` のどれが出たかを読む（zedBSD の errno で N=13 は ENODEV、42 は ETIMEDOUT）。
