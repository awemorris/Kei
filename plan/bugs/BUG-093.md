# BUG-093: Noct の source の stamp が patch の mtime に依り、新しい worktree で make toolchain が止まる

Bug ID: `BUG-093`
Reproduction: reproduced（2026-09-28、BUG-089 の agent の worktree）
Disposition: tracking
Date: 2026-09-28
Source: ws073-p027（BUG-089）
Owner: WS046（[ws046-p016](../ws046/phase016/phase.md)、2026-10-03 Q1 の割り当て）

## 観測

`userland/base/noct/Makefile` の `$(NOCT_HOST_SOURCE_STAMP): $(ZEDBSD_NOCT_PATCHES)` が patch の mtime に依るため、checkout で patch が新しくなった
worktree では `make toolchain` が「Noct: refusing to replace existing source tree: build/NoctLang」で止まる。拒むだけなので共有の tree は書かれない。
回避: worktree の Noct の patch の mtime を main に合わせる。

## 次の手

BUG-089 の LLVM と同じく、patch の SHA-256 を Noct の identity に入れて中身で判定する（identity の形式の移行が要る）。

## 再現と修正の提案（2026-10-03、P1、提案だけ。toolchain なので適用は Q1 の許可の後）

再現（読みと `make -n`、共有の tree には書いていない）: worktree `/home/awe/zedBSD-worktrees/p1`（`build/NoctLang` は main の共有の tree への link、
patch の mtime は 2026-10-02、共有の stamp は 2026-09-23）で `make -n ... toolchain` が `build/NoctLang` の取り出し（`tar -xzf`）・検証の stamp の
touch・`cmake --preset static` の作り直しを並べる。実行すれば取り出しの「refusing to replace existing source tree」で止まる。

共有の tree は今の patch と同じ中身: scratch で archive（SHA-256 一致）を展開して今の 0001〜0003 を当てた manifest は、共有の
`build/NoctLang/.zedbsd-source-manifest` と byte 単位で同じ。3 つの patch を連結した SHA-256 は `6f317e482eb695d5dce44d1ef2a029248d64415283ba5b5a1505fc2bba6031b6`。

提案の差分: [BUG-093-noct-identity.diff](BUG-093-noct-identity.diff)（`userland/base/noct/Makefile` だけ）。BUG-089 の LLVM と同じ形。
- identity に `patches-sha256=<host なら 0001〜0003、target なら 0001〜0004 を連結した SHA-256>` を足す（取り出しで書き、検証で照合）。
- make が読む時に stamp と identity を中身で受け入れ（`NOCT_HOST_SOURCE_ACCEPTED`・`NOCT_SOURCE_ACCEPTED`）、受け入れた tree の stamp の rule は
  前提を持たない（patch の mtime を見ない）。受け入れない時は今の rule（host は拒む、拒む時に理由を 1 行足す。target は patch の中身が違えば置き換え）。
- 移行: 共有の `build/NoctLang/.zedbsd-source-identity` に `patches-sha256=6f317e48…31b6` の 1 行を末尾に足すだけ（main が toolchain の lock を
  外して行う。tree・build・stamp は消さない）。各 checkout の target の tree（`userland/base/noct/noct`）は identity に行が無いので 1 回だけ取り出し直す。

scratch（`git archive` の複写に差分を当て、共有の tree の source を rsync で複写）での確認:
- 行の無い identity（今の共有の tree）+ 新しい mtime の patch → 取り出しへ進み、refusing と理由の行で止まる。
- 行を足した identity + 新しい mtime の patch → `make -n noct-host-source` は「Nothing to be done」。
- patch の中身を 1 行変える → 取り出しへ進む（中身の変化は今まで通り検出される）。
- `noct-host-source-verify`（行を足した複写）と `noct-target-source-verify`（新しく取り出した target の tree）が rc 0。
未実施: 実際の worktree での `make toolchain`（共有の tree の移行が先に要る）。

## 適用と確認（2026-10-03、ws046-p016）

Q1 の許可で差分を当てた（832534d70、main 69135488d）。Q1 が共有の identity に行を足した後、worktree の `make -n toolchain` と `make toolchain`（rc 0）は
Noct の取り出し・cmake をしなかった。共有の `build/NoctLang` の mtime は前後で同じ。詳細は [ws046-p016](../ws046/phase016/phase.md)。resolved にするかは Q1 の確認の後。
