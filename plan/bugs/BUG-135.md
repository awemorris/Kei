# BUG-135: stat() が数秒かかることがある（UFS、guest）

Reproduction: reproduced（P2 / q591 の診断 build、QEMU）
Disposition: tracking
Discovery: ws099-p020 / q591（BUG-125 の原因調査）
Owner: 未配属

## 観測

compositor の event loop の `zwl_preferences_tick` が `stat(~/.config/keiland/desktop.conf)` を呼び、1 回で 0.7〜6.5 秒止まっていた（loop の step ごとの時間の診断 build）。compositor 側は watcher thread へ移して回避した（P2 f1af6cc7f）。stat 自体が遅い原因（kernel の UFS・lock・I/O の待ち）は未調査。他の app の file 操作にも影響しうる。

## 再調査の契機

ネットワーク・desktop の作業で同じ遅さが見えたとき、または kernel/UFS の Phase を選ぶとき。gdbstub で stat の待ちの場所を取る。

2026-10-02 ws099-p020: QEMU の guest で sshd が 5 秒以上応答しない stall（ssh の Connection timed out during banner exchange）が、直す前と直した後のどちらの compositor でも出た。p076 の 20 回のうち 9 回で retry が起きた。sshd-session の fork・exec と login が UFS を読むので、stat の遅さと同じ根の可能性があるが、未証明（evidence: plan/ws099/phase020/evidence/sshcmp/）。
