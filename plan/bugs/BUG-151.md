# BUG-151: TCP で自分側を shutdown(SHUT_WR) すると poll が POLLHUP を返す

Reproduction: reproduced（QEMU の loopback TCP、P1 / q635、2026-10-03）
Disposition: tracking（修正の時期は S1 の後にユーザーと決める）
Discovery: ws005-p025（BUG-149 の handling）で見つかった同じ形の不具合（[BUG-149](BUG-149.md)）

- 場所: `src/kern/net/tcp.c` の `tcp_poll`（2233 行、2279〜2284 行の `socket->write_shutdown ||` で POLLHUP）。
- 観測: write → SHUT_WR → poll(POLLIN, 0) が BUG-149 の修正の前後とも revents=POLLHUP。Linux・FreeBSD は 0。
- 影響の見込み: request → SHUT_WR → poll で答えを待つ TCP の client が答えの前に起こされる（blocking なら read が待つ、nonblocking なら EAGAIN の busy loop、POLLHUP で閉じる client は答えを失う）。zedBSD の userland で SHUT_WR を使うのは AF_UNIX の 4 か所だけなので、今の影響は外部 package に限る見込み。
- 修正の案: BUG-149 と同じく、自分側の write_shutdown では POLLHUP を立てず POLLOUT を出さないだけにする。
