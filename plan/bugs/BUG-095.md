# BUG-095: capture の image の power-off が完了しない（oneshot の service から `/sbin/poweroff` を呼ぶと init と待ち合う）

Bug ID: `BUG-095`
Reproduction: reproduced（5330 の passthrough、ws075-p015 の e6-1・fe6-1 ほか、session を終えた run の全て）
Disposition: tracking
Date: 2026-09-28
Source: ws075-p015（BUG-085 の再試験の gdbstub の解析）
Owner: 未定（試験の image は WS031、init は base system）

## 観測

`plan/ws031/tests/zdesktop/` の capture の image（vkloop-hw.sh・bug085-hw.sh）で、場面の後の service `poweroff`（`run-poweroff.sh` →
`exec /sbin/poweroff`）の後も machine が halt しない。compositor は SIGTERM で正常に終わる（`ZWL EXIT ... error=0`）が、4 CPU は
`sched_idle`（halt ではない）。これまでの run は run-parity-vk.sh の `timeout 360` で QEMU を終えていたので気付かれなかった。

gdbstub（e6-1、`plan/ws075/tests/bug085/procs.py`・`kstack.py`・`ustack.py`）:

- 最初は CPU0 が 100%: `/sbin/poweroff` が `zsv1_client_call` → `zsv1_client_exchange_fd` → `receive_response` → `wait_ready` の
  `poll`/`recv` を回る（gdb の標本は recv・user page の pin・socket の参照。`poll` が準備ありを返し `recv` が EAGAIN と見られる。応答の期限 `ZSV1_CLIENT_TIMEOUT_SECONDS` = 310 秒まで）。
- 310 秒の後: process は init（main の `sleep(1)` の loop、`action_requested` は 0）・syslogd・login だけ。power-off の要求は処理されなかった。

## 原因（コードの読み、未修正）

init は `type=oneshot` の service を同期で走らせる（`userland/base/init/main.c` の `start_service` の `waitpid(child, &status, 0)`）。
試験の `poweroff` の service は oneshot なので、init はその終わりを待ち、`/sbin/poweroff` は init の control socket の応答を待つ。
init は main の loop（`accept4`）に戻らないので、client の 310 秒の期限まで両方が待ち、要求は失われる。client の待ちが CPU を回すのは（未確認）、
受け付けられていない unix stream の接続で `poll` が準備ありを返すため（kernel の socket の readiness、別の調査）。

## 次の手

- 試験の image: `plan/ws031/tests/zdesktop/poweroff` を `type=daemon`（restart なし）にするか、`run-poweroff.sh` を背景で走らせる。
- init: oneshot の service が control socket を使えるように（oneshot の待ちの間も要求を受ける、または oneshot を非同期に）。base system の判断。
- kernel: 受け付け前の unix stream の client の `poll(POLLIN)` の答え。
- 当面、`plan/ws075/tests/bug085/b085-watch.py` は capture の lease の release を session の終わりとし、60 秒後に CPU が halt したかを
  `poweroff` の印に書いて QEMU を終える。
