# BUG-149: AF_UNIX stream で自分側を shutdown(SHUT_WR) すると poll が常に POLLERR を返す

Reproduction: reproduced（(a) P1 / q631 の Venus・RTL8822BU passthrough と q635 の lean の QEMU、(b) q635 の QEMU で busy loop を観測。(c) は読みだけ）
Disposition: resolved（[ws005-p025](../ws005/phase025/phase.md)、統合 cb3da62d1、QEMU で確認。実機は S1。同じ形の TCP は [BUG-151](BUG-151.md)）
Discovery: ws005-p020 / q631-i01・i02（2026-10-03、P1 generation6・7）

## 期待と観測

- 期待: 自分側の `shutdown(SHUT_WR)` は POLLOUT を出さなくするだけで、相手の答えが届くまで poll(POLLIN) は待つ（Linux・FreeBSD の挙動。POSIX の POLLERR は error の印）。
- 観測: `SO_ERROR` は 0 のまま、poll が即座に POLLERR を返す。
- 場所: `src/kern/net/unix-socket.c` の stream の poll（2523 行付近 `if (socket->write_shutdown || socket->lifecycle != SOCKET_OPEN) result |= POLLERR;`）。汎用の `src/kern/net/socket.c` の poll（1053 行付近 `else if (socket->write_shutdown) result |= POLLERR;`）も同じ設計。

## 影響（request を書いて SHUT_WR し、poll(POLLIN) で答えを待つ client）

- (a) libkeiland の `network-zedbsd.c` の `network_readable` が即「読める」と判定し、2 秒の timed read が答えの前に時間切れ → 2 秒を越える request（join）が EIO。Settings の誤った鍵の join で EIO、試験 client で i=0・err=5。回避の修正（poll の後に `recv(MSG_PEEK|MSG_DONTWAIT)`）は P3 の ws131-p003 の `43c9fb90c`（未統合）。
- (b) `userland/base/service/zsv1-client.c`: socket は SOCK_NONBLOCK、wait_ready(POLLIN) が即返り recv が EAGAIN → 答えまで CPU の busy loop（機能は通る見込み、未観測）。
- (c) `userland/desktop/sessiond/greeter.c` の `sessiond_greeter_release`: SHUT_WR の後の `sessiond_read_line`（main.c）は poll が即返り、socketpair が blocking なので read が block する → `GREETER_RELEASE_MS` の上限が効かない（未観測）。
- (d) net の CLI（`protocol.c` の wait_input）: blocking read と SO_RCVTIMEO で上限が効くので機能の影響は無い見込み（読みからの判断、未観測）。

## 修正の案（未実施）

両方の poll から「自分側の write_shutdown で POLLERR」を除き、POLLOUT を出さないだけにする。`lifecycle != SOCKET_OPEN` の扱いは別に確かめる。修正したら (a)〜(c) の回避の要否を見直す。

2026-10-03 user「P1の試験が終了してclearedになったら、BUG-149をP1で取り組んでもらってください。」→ q635 を P1 に予約。
