# BUG-105: 素の 5330（demo-lcd3）で USB マウス（logi M650）が使えない

Bug ID: `BUG-105`
Reproduction: reproduced（ユーザー、素の 5330、demo-lcd3、2026-09-29）
Disposition: tracking
Date: 2026-09-29
Source: ユーザー「demo-lcd3は実機でUSBマウスが認識されませんでした。確認してほしいです。logi M650です。」
Owner: WS073（[ws073-p032](../ws073/phase032/phase.md)）

## 観測

- M650 を USB で使うときは Logi Bolt の USB 受信機（Logitech、vendor 046d）を経由する。
- 同じ日の demo-lcd2 の起動で main が ssh で読んだ Kei の `lsusb` に Logitech の device は無かった（webcam 0c45:6d1d、指紋 0a5c:5842、
  USB の storage 30de:6545、USB の LAN 0bda:8156 だけ）。そのとき受信機が挿さっていたかは未確認。
- 5330 の Linux（2026-09-29 19 時台）の `lsusb` にも受信機は無い（挿さっていない）。

## 調べること

1. 受信機を 5330 に挿して Linux で `lsusb -v -d 046d:` と HID の report descriptor（`/sys/kernel/debug/hid/*/rdesc` か `usbhid-dump`）を取る。
2. 素の Kei で同じ port に挿して `lsusb` に出るか（列挙の段階か、HID の段階か）。
3. HID の段階なら、取った report descriptor を `src/drivers/usb/usb-hid.c` の parser に host で通す（report ID 付きの report protocol、
   受信機の複数の interface: keyboard・mouse・HID++ の vendor）。

## 2026-09-29 main の調査

- 5330 の Linux で受信機を読んだ: `046d:c548 Logi Bolt Receiver`（USB 2.0、bcdDevice 5.01）、interface 0（boot keyboard、descriptor 67 byte）、
  1（boot mouse、133 byte: report ID 2 = button 16・X/Y 16 bit（-32767〜32767）・wheel 8 bit・AC Pan 8 bit、ID 3 = consumer、ID 4 = system control）、
  2（vendor の HID++、54 byte）。descriptor は `plan/bugs/bug105/logi-bolt-c548-if{0,1,2}.rdesc`。
- host の試験 `plan/bugs/bug105/run-hid-bolt.sh`（`drv_hid_report_layout_parse` に 3 つを通し、mouse の report を decode）: **3 つとも parse が失敗**
  （interface 0 は 3、1 と 2 は 21）。Kei の HID の driver は interface ごとに layout の parse を要し、失敗すると publish しないので、
  列挙されても mouse にならない。これが原因の最有力（列挙の段階は素の Kei で未確認）。
- 次: parser がどの item で拒むかを特定して直す（WS073 の Phase）。素の Kei での確認はユーザーの起動の後。

## 2026-09-29 ws073-p032（修正、host で確認。実機は未確認）

- 拒んだ item（gdb で `parse_input`・`add_field` の戻り値を追った）:
  - interface 0: 112 bit の key の bitmap（usage 0x04〜0x73）で、usage 0x31 と 0x32 が両方 `KEY_BACKSLASH` になり、`add_field` の「同じ report の同じ event の
    2 つ目の field」の規則で EINVAL。
  - interface 1: report ID 4（System Control）の array が usage 3 つの列挙で、array は「1 つの range」でなければ page を見る前に EOPNOTSUPP。
  - interface 2: vendor page の array（usage 1 つ、range でない）で同じ EOPNOTSUPP。
- 修正（`src/drivers/usb/usb-hid.c`）: key の field は重複を許す（decoder は key の field の和で押下を決める）、keyboard の usage を持たない array は読み飛ばす、
  Consumer の AC Pan（relative）を `REL_HWHEEL` に。interface 2（HID++）は publish する field が無いので従来の最後の規則で EOPNOTSUPP になり、driver は使わない（期待どおり）。
- 確認: `plan/bugs/bug105/run-hid-bolt.sh` PASS（if0・if1 の parse、mouse の report の BTN_LEFT・REL_X +5・REL_Y -3・REL_WHEEL +1・REL_HWHEEL -2、
  keyboard の report の KEY_LEFTSHIFT・KEY_A・KEY_BACKSLASH）。HID の host 試験 3 本（pen・touch・scantime）ok、vmunix warning 0、QEMU の boot test PASS。
- 残り: 素の 5330 での確認（ユーザー）。列挙の段階（`lsusb` に出るか）も未確認。
