# BUG-120: 窓を 30 個ほど開くと、GPU の object の枠（128）が尽きる（`gt memory: object pool exhausted`）

Bug ID: `BUG-120`
Reproduction: reproduced（5330 の passthrough、ws075-p025 の stress、2026-09-30）
Disposition: tracking
Date: 2026-09-30
Source: ws075-p025 の途中報告
Owner: WS075（i915 の GT の memory）

## 観測

BUG-117 の stress（`plan/ws075/tests/hdmi/stress-117.sh`）で窓を 30 個まで開くと、`gt memory: object pool exhausted` が出る。GPU の object の
pool の枠が 128 で固定されている。BUG-117（executor の表の競合）とは別の制限。デモの台本（窓 10 個）では出ていない。

## 次にすること

pool の大きさを動的にするか、上限を上げる。窓の数ごとの object の数を数え、何個の窓まで持つかを記録する。

2026-10-03 user（優先度と依存）: 標準。BUG-052 の後に P1。

## BUG-144 との関係（2026-10-03、q643、P1、読み）

`I915_GT_MAX_OBJECTS` 128（`src/drivers/gpu/i915/memory.h`）は i915 の driver の表で、QEMU の Venus（BUG-144）は使わない。BUG-144 の上限は Venus の
host-visible の aperture（hostmem）で別の仕組みだが、どちらも固定の枠を多くの窓・app が分け合って尽きる形。Model viewer 1 個は i915 で約 20 の object
（texture 14 枚ほか）を使う見込みで、5330 では 5〜6 個で先にこの枠に当たる。詳細は [ws014-p011](../ws014/phase011/phase.md)。
