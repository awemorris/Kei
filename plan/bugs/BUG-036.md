# BUG-036: USB の CDC-ECM の network adapter の attach が error 3 で失敗することがある

Bug ID: `BUG-036`
Reproduction: reproduced（QEMU、amd64 guest、間欠、1 回）
Disposition: tracking（2026-09-27 に緩和（列挙の再試行）を入れた。時間切れの原因は未解明）
Date: 2026-09-24
Source: ws046-p008（q412-i01）で、harness（`plan/tools/guest/guest.py`）の guest に 2 台目の usb-storage（xHCI の port 4、1 GiB の UFS の image）をつないで起動したとき。
Owner: none（未割当）
Queue: none。

## 期待と観測・影響

期待: harness の usb-net（CDC-ECM、`0525:a4a2`、xHCI の port 2）が attach され、SSH で guest に入れる。

観測（serial の console で `dmesg`）:

```
usb0: device 3 port 6 0525:a4a2 class 02 configuration=1 configured
usb0: device 3 interface 0 class 02/06/00 driver=usb-cdc-ecm attach-failed error=3
usb0: device 3 interface 1 class 0a/00/00 no-driver
```

`ifconfig -a` は `lo0` だけ。sshd は動いているが host からの SSH は banner の交換で時間切れ（QEMU の log に `Slirp: Failed to send packet`）。
同じ構成（2 台目の usb-storage が port 4）の起動は q412 で他に 4 回あり、どれも network が上がった。2 台目の disk が無い既定の構成で見たことは無い（未確認）。

影響: guest の harness が SSH で使えなくなる（serial の console は使える）。

## 再開の条件

USB の CDC-ECM・列挙を扱う WS で。error 3 の意味（`attach` のどの段で返るか）を gdbstub で調べる。受け入れ案: 2 台目の usb-storage をつないだ起動を 20 回して全て network が上がる。

## 追加の観測（ws054-p002、q414-i01、2026-09-25）

同じ構成（2 台目の usb-storage を xHCI の port 4）で、続けて 2 回 SSH できなかった。2 回目は serial の console で:

```
xhci: port 6 reset complete portsc=00000603
usb0: port 6 enumeration failed (42)
```

usb-net（QEMU の port 2、guest の port 6）の列挙そのものが error 42 で失敗し、device が現れない（1 回目の attach の失敗 error 3 とは段が違う）。
error 42 は [BUG-030](BUG-030.md)（起動時の USB の間欠の error 42）と同じ値。2 台目の usb-storage をつないだ起動で、q412〜q414 の約 9 回のうち 3 回。
回避: 作業の disk を usb-storage でなく NVMe（`-device nvme,serial=...,drive=...`、guest で `/dev/nvme0n1`）でつなぐ。

## 再現と緩和（2026-09-27、WS073、[ws073-p017](../ws073/phase017/phase.md)）

- 再現（修正の前の kernel）: USB から起動する 20 回で 2 回、2 台目の usb-storage をつないだ 20 回で 1 回、SSH が上がらない。1 回は serial の
  console で `usb0: port 6 enumeration failed (42)`（usb-net）と lo0 だけの `ifconfig -a`。
- 緩和: root port の列挙が ETIMEDOUT・EIO なら reset から 3 回まで繰り返す（`src/drivers/usb/usb.c` の `root_port_enumerate()`、commit d306209f）。
- 確認: USB の起動 disk と 2 台目の usb-storage の 20 回で全て SSH と ue0。5 回で最初の列挙が ETIMEDOUT（port 7）になり、再試行で成功した。
- 残り: 列挙の 1 段が時間切れになる原因（xHCI の event の取りこぼしか QEMU か）。hub の下の port の再試行。

## 時間切れの原因（2026-09-30、[ws073-p042](../ws073/phase042/phase.md)）

列挙の時間切れも [BUG-116](BUG-116.md) と同じ機構（command の poll の間の IMAN.IE の上げ下げで QEMU の xHCI の MSI-X の割込みが捨てられる）と見られる。
p042 の修正の後、USB の起動 disk の 80 回（TCG 2×20、KVM 2×20）で `enumeration failed (42)` は 0（修正前は p041 の試験で TCG 75 回に 9、KVM 40 回に 4）。
2 台目の usb-storage をつないだ構成は試していない。resolved にするかは main の判断。
