# BUG-124: QEMU の Venus で Model viewer の窓を大きくすると vkCreateSwapchainKHR が VK_ERROR_DEVICE_LOST で失敗し app が終わる

Bug ID: `BUG-124`
Reproduction: reproduced（QEMU の Venus、Files と PDF Viewer の上の Model viewer の resize で 40 回中 5〜6 回、2026-09-30）
Disposition: tracking
Date: 2026-09-30
Source: ws099-p011（BUG-121）の報告（P5）
Owner: 未定（libvulkan と Venus の側、WS014・WS031 の領域）

## 観測

- `plan/ws099/tests/resize-stress.sh` で、Files と PDF Viewer を先に開けた上の Model viewer を大きくすると、`vkCreateSwapchainKHR` が
  result=-4（VK_ERROR_DEVICE_LOST）、errno=8 で失敗し、app が終わる。40 回中 5〜6 回。5 つの app の上では起動のときにも同じ失敗が出る。
- log の順は `ZWL CLIENT gone ... reason=read` が `MVIEW FAILED` より先で、client の側が先に切っている。compositor は窓を落としていない。
- 5330 の実機（i915）では、角の drag 20 回で起きていない。
- hostmem=1G で比べようとしたが、session が起動しなかった。

## 見当（未調査）

Venus の host の資源（blob の memory、hostmem の上限）の不足か、libvulkan の Venus の経路の swapchain の作り直しの誤り。

## 再調査の契機

Windows の QEMU（WS085、Venus）のデモで Model viewer を使う場面があるので、台本の touch の場面で起きたら優先を上げる。
