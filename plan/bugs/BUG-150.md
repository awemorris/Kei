# BUG-150: Terminal で Emacs を起動すると、画面の描画が 2 行目から始まって見える

Reproduction: reproduced（ユーザーの報告、FreeBSD の Keiland の Terminal、2026-10-03。host の replay で FreeBSD・Linux の Emacs の列とも再現）
Disposition: resolved（ws128-p010、統合 02c0d6f41。user「FreeBSDで問題なく動作したら、test passとしてマージしていいです。」）
Discovery: 2026-10-03 user「FreeBSDで確認できたバグなのですが、TerminalでEmacsを起動すると、カーソル移動のVT100互換シーケンスに問題があるようで、開始が2行目からになっているように見えます。off-by-oneではないでしょうか。ゼロスタートか1スタートかみたいな。」

## 読みの所見（Q1、2026-10-03、未検証）

- `userland/desktop/terminal/screen.c` の CUP（`CSI row;col H`・`f`）、VPA（`d`）、CHA（`G`）、DECSTBM（`r`）は 1 起点を 0 起点に直していて、一見 off-by-one は無い。
- 子の `TERM=xterm`（`main.c` の 796 行）。FreeBSD の xterm の terminfo の初期化・smcup の列（例: `CSI ?1049h`、`CSI !p`（DECSTR）、`CSI 22;0;0t`、`ESC 7`/`ESC 8`）のどれかの扱いの違いか、端末の大きさ（`TIOCSWINSZ` を `forkpty` の後に設定、856 行）が子の起動の時点で反映されていない可能性。
- 次: FreeBSD で `TERM=xterm emacs -nw` の出力を `script` などで取り、Terminal が受けた escape の列を特定する。zedBSD・Linux でも起きるかを確かめる。

2026-10-03 user「BUG-150は今実行してOKです。FreeBSDホストを空けたので使ってください。Emacsは入ってます。」→ P2 generation4 の q636（ws128-p010）、N=3。

## 原因と修正（P2 generation4、2026-10-03、ws128-p010）

- 原因: `userland/desktop/terminal/screen.c` の `screen_put()` が最終列に字を置いた直後に次の行へ wrap していた。xterm・VT100 は最終列に留まり wrap を保留する（terminfo の `xenl`）。Emacs は menu bar・mode line を 80 桁ちょうど書いて `\r\n` で進むので 1 行余分に下がり、mode line を最下行の手前に書くと scroll して画面全体がずれた。CUP などの 1 起点の扱い・FreeBSD の terminfo（`smcup` 無し）は原因ではない。3 OS 共通の source なので zedBSD・Linux でも同じ。
- 修正: `terminal.h` の `wrap_pending`、`screen.c` で保留・取消。
- 証拠: host `plan/ws128/tests/terminal-p010.sh`（FreeBSD 15.1 の Emacs 31.1 と Debian の Emacs 30.1 の記録の replay、wrap の単体）が修正前 FAIL、修正後 PASS（Linux host と FreeBSD 実機）。FreeBSD 実機の native build exit 0。詳細は [ws128-p010](../ws128/phase010/phase.md)。Terminal の実物の目視は未実施。
