## 期待と観測・影響

期待: `make -f plan/ws001/tests/directory-fsync-host-test.mk run` で UFS・VFS・overlay の host 試験が通る。

観測:

1. `src/kern/io-stats.c` を link しようとして失敗（refactor `abb8b256` で `io.c` に統合された）。参照を外すと（ws054-p002 で外した）、
2. `vfs-test` の link で `file_fsync_backend` が二重定義（`src/kern/file.c` と試験の両方が定義する）。
3. `ufs-test` は `plan/tools/driver-fragments/prepare.py --source src/drivers/fs/ufs.c` の断片（`build/driver-fragments/src/drivers/fs/ufs/ufs-vfs.c` ほか）から build するが、
   `prepare.py` が `Missing or ambiguous production section: src/drivers/fs/ufs/ufs-allocation.inc` で止まる（`ufs.c` から断片の区切りが無くなった）。
   全体では `src/drivers/disklabel/pc98-auto.c` で同じく止まる。

影響: UFS の driver を host で試験できない（WS001・WS004 の AX211・xHCI の host 試験も同じ道具を使う）。ws054-p002 は guest の試験と、image を host の検査（`tools/build/check-ufs-image.py` の fsck 相当）で確かめる方法に替えた。

## 再開の条件

host 試験の土台を扱う WS で。受け入れ案: `prepare.py` が今の source から断片を作れる（または断片に頼らない host 試験の build）、`directory-fsync-host-test.mk run` が通る。

## 2026-09-27 WS073 の再調査（一部を修正、残りは host 試験の土台の WS へ）

- VFS の fixture: `file_fsync_backend` の二重定義は、試験の stub を VFS の fixture（本物の `file.c` を link する）で外して解消
  （`plan/ws001/tests/directory-fsync-host-test.c`）。`make -f plan/ws001/tests/directory-fsync-host-test.mk OUT=build/ws073-bug039
  build/ws073-bug039/vfs-test` が build でき、`ws001-p016 VFS dispatch: PASS (13 checks)`。
- overlay の fixture: `KERN_PATH_MAX` を今の名前 `KERN_PATH_MAX` に直した後、`overlayfs.c` の link が inode・kmem・mount・file の多数の
  未定義で止まる。`overlayfs.c` の関数が `.hightext` の明示の section に置かれ、`-ffunction-sections`・`--gc-sections` で使わない関数を
  落とせなくなったため（以前は落ちていた）。直すには fixture が stub を大量に持つか、host の build で section の属性を外す仕組みが要る。
- UFS の 2 つの fixture: 以前のまま（`prepare.py` の断片の区切りが `ufs.c` に無い。試験は `plan/ws025/temp/` の消えた断片の header も include する）。
- 判断: 残り（overlay・UFS）は host 試験の土台を扱う WS の仕事として tracking のまま。WS073 では VFS の fixture の修正だけを入れる。

## 再見積もり（2026-10-03、q643、P1、読みと host の試し build だけ。修正していない）

- UFS の driver は `src/drivers/fs/ufs.c` の 1 file（20,690 行）になり、fixture が頼る断片（`build/driver-fragments/.../ufs-vfs.c`、`prepare.py` の区切り）は
  もう作れない。`ufs.c` を host の cc で直に compile すると、kernel の header（`include/kern/clock.h` の `UINT32_C` ほか）が host の libc の header と
  ぶつかって最初の数行で止まる。overlay は前の記録どおり `.hightext` の section で未定義 125。
- 直すには、host 試験の土台（kernel の header を host で読める形にする、または kernel の source を host の build で使う時の互換の層と stub の一式）を
  作る仕事が要り、1 つの Bug の修正の規模を越える。q643 の「実機なしで直せる」順からは外し、host 試験の土台の WS を立てる判断を Q1 に依頼した。
