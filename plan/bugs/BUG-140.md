# BUG-140: Files の Trash で同名の 2 つ目が `名前.2`・種類「2」で出る

Reproduction: reproduced（P4 / q595、QEMU Venus。host の試験でも再現）
Disposition: resolved（q616-i01、P1、2026-10-03）
Discovery: ws127-p001 / q595。Trash に同じ名前の file を 2 つ入れると、2 つ目が `Budget.csv.2`（種類 "2"）と表示され、本来の名前 `Budget.csv`（CSV）にならない。[requirements](../ws127/requirements.md) §3 の B1。

## q616-i01（P1、2026-10-03、ws127-p002）: 直した

- 原因: `dir.c` の `fm_dir_read_trash` が Trash の `files/` の中の名前（2 つ目は `NAME.2`）をそのまま表示の名前にし、種類もその名前から決めていた。
- 直し（commit `b90364e74`）: trashinfo の `Path=` の最後の部分を表示の名前にし、種類をその名前から決め直す。path（Trash の中の実体）は変えないので、
  Put Back・Delete Immediately は従来どおり。
- 確認（host）: `plan/tools/files/host-model.c` に「Trash の一覧で `NAME.2` が元の名前・種類で出る」check を足した。直す前の `dir.c` では FAIL、
  直した後は PASS（`sh plan/tools/files/host-model.sh` → `files-model: PASS`）。QEMU の Venus の `files-regress.sh` の Trash の試験（p004）も PASS。
