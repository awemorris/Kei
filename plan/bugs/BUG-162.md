# BUG-162: desktop.conf を Settings と zdesktop の間のやり取りに使っている（file の poll）

Reproduction: reproduced（code の読み、Q1、2026-10-03）
Disposition: tracking（設計の直しの WS を Q1 が立てる。ユーザーに報告済み）
Discovery: BUG-161 の後のユーザーの問い「もしかしてこのファイルを参照しているリーダーがいますか？確認してください。そうであればその設計はまずいです。」

2026-10-03 user「desktop.confに書き込むのはコンポジタの都合であって、それはログインセッションの終了時に書き込んで再開時にロードするようにします。それ以外に書き込む必要はないです。」「デスクトップから変更する音量は。audiodに依頼をするのであって、あとのことはaudiodに任せてください。」

## 今の設計（main、2026-10-03 の読み）

- `~/.config/keiland/desktop.conf` は libkeiland の preferences（`userland/desktop/libkeiland/preferences.c`）の key=value の file。
- Settings（`settings/look.c`）が壁紙・窓の透明度・pointer の速さ・wheel の向き・key の repeat を選んだ時に書き、1 秒ごとに読み直す。
- zdesktop（`wayland/preferences.c`）は watcher の thread で 1 秒ごとに file を stat・読み、変わった key を適用する。つまり file が Settings → compositor の通信路になっている（読み手が 2 つ、書き手が 2 つ）。
- 音量（sound.volume・sound.muted）は BUG-161（efc5ea7fc）で、操作では書かず、zdesktop が session の終わりに書き、最初に一度読む形になった。

## 求める設計

- desktop.conf は compositor の持ち物。session の開始で読み、終わりで書く。それ以外に読み書きしない。他の process は読まない。
- Settings からの変更は compositor へ protocol（Wayland の要求）で送り、compositor がメモリに持って適用する。Settings の表示は compositor から値をもらう。
- 音量は audiod へ頼むだけ（今も audiod の device の volume、mixer か soft volume）。
