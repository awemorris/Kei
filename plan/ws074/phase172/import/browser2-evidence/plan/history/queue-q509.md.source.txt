## Approved scope / design snapshot

## Purpose and prerequisite

Restore parser-time document.write/writeln so scripts can insert real HTML at
that point in the document. p102's [inventory](../ws074/phase102/inventory.json)
shows that the original Acid3 body cannot create its map, forms, table, or
iframes. This is a prerequisite, not a promise of full Acid3 clearance.
p102 must clear before selection. Child browsing contexts remain separate work.

## Bounded scope and design

Use the existing parser script hook, UTF-16 input stream and DOM bindings.
Introduce insertion into the active parser's current input position; do not
append an independently parsed fragment at the end of body. Support multiple
arguments, writeln's newline, partial tokens across calls, and nested inline
scripts with bounded recursion and preserved script execution order. Propagate
allocation/parse failures through existing page/binding error paths.

Before selection, inspect the active parser's ownership and lifetime through
page_parse/script hooks. Specify the behavior outside an active parser and its
relationship to document.open/close in a plan revision; do not silently provide
a fragment substitute. If this requires a major architecture decision, stop the
dependent implementation and record options. Existing design §3 already intends
parser insertion; ordinary implementation details remain delegated.

Affected scope: browser html/, bind/, page/ and focused WS074 tests. Apply
[Guardrail](../guardrail.md), full [C standard](../coding-style.md),
[design](../ws074/design.md) §§3,4,14. No iframe, XML, Range/Traversal, CSSOM, rendering
exceptions, HAL, toolchain, or ES-module changes.

## Authorized design revision (2026-09-30)

Current user: 「次のqueueを実行してください。」 authorizes q509 / p103.
The initial parser is owned by page_load_html until feed/finish return, and its
script hook runs synchronously. Publish that parser only for this lifetime and
clear the pointer before destruction. The parser owns a scoped insertion point
for each script; preserve the outer point when inserted scripts recurse.

During write, keep the unread suffix in a temporary owned buffer, append the
written UTF-16 units at the insertion point, run only the available prefix with
EOF disabled, then restore the suffix. Preserve tokenizer state across calls,
including partial tags, references and surrogate pairs. Bound nested writes to
32 and propagate memory/parse errors. A lazy CR/LF fold covers raw written units
without applying network append normalization to insertion text.

Outside an active parser (and for foreign documents), return an explicit
NotSupportedError: script-created parsers and implicit/explicit document.open /
close are deferred to a later Phase. This is an advertised limitation, not a
claim of conforming late writes or a fragment fallback. No open/close methods
are introduced here. No acceptance change: this Phase covers parser insertion.

Reference: [WHATWG HTML dynamic markup insertion](https://html.spec.whatwg.org/multipage/dynamic-markup-insertion.html#document.write()).
The standard's late-write replacement requires the deferred script-created
parser lifecycle; the supported parser-time path follows its input insertion
and synchronous token processing model. Compare supported fixtures to Chromium
and separately verify the explicit unsupported-call behavior.
