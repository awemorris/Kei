## Exact scope / design / criteria

Add bounded DOM C foundation dom_form_listed(element), dom_form_control_member(element)
and dom_form_owner(element) for ordinary live trees without parser-special persisted
associations. Listed built-ins button/fieldset/input/object/output/select/textarea
require actual HTML namespace and exact local case; img associated but not listed.
Control-member predicate excludes input image state via exact ASCII-case-insensitive
type keyword, keeps hidden/disabled/unnamed listed members. No custom-element system.

Owner query performs no allocation/user script/caching/raw realm. For listed control
with no-namespace form attribute and connected Document root, find first tree-order
element with exact nonempty ID matching attribute. That first matching element must
be actual HTML form or result null (including duplicate ID on nonform/foreign).
No nearest-form fallback when connected explicit attribute exists but misses.
Otherwise use nearest actual HTML form ancestor; detached trees/DocumentFragments
and nested script-created forms handled by ordinary ancestry. Detached explicit
attribute falls back to ancestry per connected condition. Nonassociated nodes null;
img ignores form attribute and uses ancestry. Recompute after moves/removal/reorder/
form or id changes, never retain stale ancestor/owner state.

custom elements, public JS input.form/HTMLFormElement/form.elements/RadioNodeList/
reflection/activation/submission/radio grouping are known later requirements and

association or parser conformance claim. Needed by later control collection and
