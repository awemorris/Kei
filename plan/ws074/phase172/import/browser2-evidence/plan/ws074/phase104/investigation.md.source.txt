## Bounded reproduction

The new [realm probe](../tests/realm-context-probe.c) creates two realms in one
heap, installs their built-ins, and exposes the child global to the parent.
Parent `marker` is 11; child `marker` is 22. These are ordinary supported
embedding operations; no iframe binding or dangling-pointer call is involved.

Run after `sh plan/ws074/tests/host-build.sh plain` and `asan`:

```sh
python3 plan/ws074/tests/run-realm-context-probe.py
```

The runner checks existing engine objects against source/header timestamps,
compiles the probe with `-std=gnu11 -O1 -g -Wall -Wextra -Werror`, and links the
same engine as the host build. ASan adds address/undefined sanitizers and uses
`ASAN_OPTIONS=detect_stack_use_after_return=0` for the conservative collector.
Both variants compile without warnings, exit **1**, and report the same
**3/8 passing, 5 failing** inventory. Neither produces sanitizer/stderr output.
Reproducing failures is investigation evidence, not passing acceptance.

## Source evidence and lifetime gap

- `vm/interpreter.c:1355`: bytecode calls push the child function into
  `run->realm` and retain that realm as the execution environment.
- `vm/interpreter.c:1368,1431`: native/constructor paths execute in the callee
  realm but return the thrown status without copying its exception to the
  caller realm. `vm/function.c:400,443` has the same transport gap in VM APIs.
- `vm/realm.c:88,112,296`: malloc-owned realms remain permanent heap tracers
  until `vm_realm_destroy`; destroying them frees the VM stack and C record.
- `vm/function.c:516`: function tracing covers its object/code/environment/data,
  but does not retain the C realm referenced by `function->realm`.
- `bind/window.c:159,184,1172`: windows similarly rely on a manually destroyed
  C record/tracer. Keeping every detached frame forever would retain its realm,
  globals and stack; immediate destruction would invalidate saved functions.

The lifetime gap is a design prerequisite, **not** a reproduced use-after-free:
the probe retains both realms until all calls finish. The existing embedding
contract requires realms to outlive functions. Child contexts need a separate
reachability-based ownership plan consistent with browser design §§1,4,11.
