# ws074-p104: Initial HTML iframe child contexts

Status: cleared
Disposition: normal
Parent: [WS074](../ws.md)
Queue: q515 / q515-i01; q510-i01 and q513-i01 remain uncleared history
Prerequisites: [p103](../phase103/phase.md) cleared; [p105](../phase105/phase.md)
and [p106](../phase106/phase.md) must clear before resumption

## Objective and finite scope

Establish real initial about:blank child contexts for HTML iframes: distinct
Document/Window, contentDocument/contentWindow, parent/top relationships and
lifetime within the existing single-process browser. p103 restored the Acid3
iframe elements, but their child documents remain absent. This Phase establishes
the context foundation; URL loading, XML/SVG and object documents are subsequent
work, not a claim of complete iframe or Acid3 support.

## Design and readiness

Before activation, inspect wrapper identity, document ownership, per-document
realm behavior and GC tracing, the parser's element-insertion path and frame
removal/destruction. Preserve the existing one-agent-per-tab architecture;
new child documents need a verified ownership model, not parent Window aliases.
Record exact affected APIs, supported lifecycle and failure paths before code.
Resolve any major architecture/product decision before dependent implementation.

Bound implementation to initial about:blank HTML contexts, synchronous access
once an iframe is connected, and parent/child cleanup. Document foreign-origin
and source-loading limitations explicitly; do not expose unverified remote
content as same-origin. No network loader, navigation, Window.open, XML/SVG,
object, Range/Traversal, CSSOM, HAL, toolchain or ES-module implementation.

Apply [Guardrail](../../guardrail.md), full [C standard](../../coding-style.md),
and [browser design](../design.md) §§1,4,9,14. Planned affected areas: page/,
bind/, DOM ownership hooks and focused WS074 tests. No unrelated modules.

## Proposed acceptance

- Separate child Document/Window identity and correct parent/top relationships
  for connected initial about:blank iframes; supported fixtures match Chromium.
- Nested frames, disconnected elements, removal and page teardown have defined,
  verified ownership without dangling cells or accidental parent-document alias.
- Plain/ASan builds, focused lifecycle/GC/error regressions, Acid2 exact
  preservation, existing DOM regressions and all 100 Acid3 results recorded.
- Full changed-source standards review, style check and diff check; no claim
  that initial contexts satisfy URL-loading/XML requirements or p100.

## q513 concrete design / resumption (2026-09-30)

p105/p106 verified in f39fdea9/f8c12297; latest clean baseline bc4d4ef7.
q512 archive read back. Root executor, one Phase, no concurrent Queue. Current
user's exact Acid3 autonomous/automatic Queue instruction authorizes this attempt.
q510's earlier uncleared outcome and evidence remain unchanged.

Add bind/frame.c and register it in libbrowser/Makefile. Use existing manual
interface-table convention: HTMLIFrameElement extends HTMLElement with distinct
contentWindow/contentDocument getters. Resolve wrappers from each node's Document
owner window rather than the calling realm; preserve existing cached wrappers.
Document stores an opaque view pointer and removal callback, and the existing GC
context cell retains managed owners. DOM includes no bind headers.

On first synchronous getter for a connected HTML iframe in an active Document,
create a managed child realm in the parent heap, sharing the parent's well-known
symbols before built-ins (same tab agent). Create an about:blank quirks Document
with html/head/body, then its own Window/prototypes. Use only bounded blank host
callbacks (console/User-Agent inherited, constant about:blank location); no async
fetch, parser insertion, navigation or foreign resource callbacks. Publish the
iframe's traced child realm only after successful construction; failed cells
remain collectible. Bound nesting to64 and report RangeError beyond it. Creation
is lazy at synchronous observation; initial load-task dispatch is subsequent
loading/parser work, not supplied or claimed by this initial-context Phase.

Trace iframe element → managed realm → Window/Document; child Window traces
parent/top global objects and frame element. Window getters for parent/top/
frames/closed/frameElement use the receiver's immutable own document property
to validate its identity across realms; no fake Window alias or new WindowProxy.
Document.defaultView returns its active owner global or null when detached;
URL/readyState use the Document's owner, including borrowed accessors.

DOM removal calls its Document callback before unlinking. Retire contexts in the
removed subtree, clear element-owned child references and child's frameElement,
then idempotently detach child Window and recursively retire nested children.
Bounded context depth limits recursion. Inactive old Documents cannot create new
children; reinsertion creates a fresh context. Primary Window destruction retires
child contexts and clears its Document view hooks while cells are still live;
managed finalization continues to avoid dereferencing unrelated dead cells.

Scope: bind/frame.c, bind headers/window/environment/node/document; DOM headers/
node ownership-removal hooks; libbrowser source registry and WS074 focused tests.
No network/URL loading, sandbox implementation, navigation, Window.open, late
write/open/close, XML/SVG/object, Range/Traversal/CSSOM, HAL/toolchain/modules.
Unsupported sandbox frames expose no child objects; no unverifiable foreign
content is exposed as same-origin. WindowProxy/frames enumeration remains later.

Acceptance retains original initial-context criteria: saved Chromium17/17 in
both variants, constructor/wrapper identity and nested/disconnected/removal/
reinsert/old-document behavior; focused GC/saved function/document/host teardown/
allocation bounds; existing ownership27/27, realms30/30, VM/DOM regressions;
warning-free plain/ASan, Acid2 exact and all100 Acid3 inventory/no regressions,
full changed-source standard/style/diff review. No complete loading or p100 claim.
Reference: https://html.spec.whatwg.org/multipage/iframe-embed-object.html#the-iframe-element
