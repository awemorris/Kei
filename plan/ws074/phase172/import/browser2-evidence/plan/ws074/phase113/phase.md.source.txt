## Objective / finite scope / inspected design

Indexed95 rejects legal `a.length="2147483648"` because assignment/descriptor/
constructor paths impose signedint32 cap. Existing vm_object.length is uint32,
vm_array_set_length grows metadata without allocating dense storage, and sync
writes vm_value_number. Remove artificial signed cap for valid uint32 lengths,
preserve ToUint32 then ToNumber comparison/order (two user conversions for
ArraySetLength), RangeError for fractional/out-of-range/NaN/Infinity, constructor
numeric argument uses safe existing conversion rather than undefined C cast.
Assignment expression keeps original RHS unchanged through existing bytecode.

Allow already-normalized numeric lengths at C vm_object_define boundary and
retain requested length attributes for read-only descriptor updates. Keep density
bounded by actual element_capacity+SPARSE_GAP in widened arithmetic, not possibly
huge logical length; existing int32 indices can stay sparse after length growth.
No new property-key representation: indices >=2^31 still have existing atom-key
limitations; this Phase does not claim full uint32 index, all array method, or
nonconfigurable shrinking conformance. No interpreter/compiler/API/ABI redesign,
BigInt/typedarray/p100 other features/HAL/toolchain/module changes.
Affected vm/access.c, vm/object.c, js/builtin_array.c; focusedJS+hostcapacity cases,
existingobject/interp/realm/JS/DOM/Acid. ApplyGuardrail/fullCstandard/VMownership.
[ArraySetLength](https://tc39.es/ecma262/multipage/ordinary-and-exotic-objects-behaviours.html#sec-arraysetlength)
and [Array constructor](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-array)
ECMAScript2027draft read2026-10-01. Ordinary extension of existing uint32 metadata.
