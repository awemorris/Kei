## Exact scope / design / criteria

Add DOM-owned opaque removal registry and per-subscription opaque token, separately
C-allocated/refcounted, weak callback context (not traced GC owner). Registry has
one Document ownership plus each token ownership. Document finalizer releases its
registry ownership without reading any GC observer; token unlink uses only live
C allocations without reading Document. This permits any GC finalization order,
wholeheap teardown and dead subscriptions reclaimed while their Document remains.
Register allocation rollback/overflow bounds, NULL-safe token release. All weak
contexts must release token in their collector finalizer before context storage
is reused. Notification is synchronous C-only; callbacks cannot allocate/collect,
run script, subscribe/unsubscribe or change tree. These bounds suit iterator position
repair; user filters run later outside notifications. Exact callback order FIFO.

Hook dom_remove before existing frame retirement and unlink; detached nodes do not
notify; removal/insertion-move retain original DOM links during notification.
New dom/removal.c registered libbrowser, declarations/types/document opaque pointer
in dom/dom.h, document finalizer/hook in dom/node.c. No VM collector changes,
NodeIterator API/filter algorithms, generic observers/MutationObserver/adoption,
collections/forms/Range/CSS/loading/SVG/HAL/toolchain. DOM is owner of generic C
subscription, bindings later own iterator context/tokens. No permanent heap roots.
