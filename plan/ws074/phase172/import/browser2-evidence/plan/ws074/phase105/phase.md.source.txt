# ws074-p105: Cross-realm execution and exception transport

Status: cleared
Disposition: normal
Parent: [WS074](../ws.md)
Queue: q511 / q511-i01 (standing autonomous approval, 2026-09-30)
Prerequisites: existing shared-heap realm/function/interpreter APIs verified;
q510 [reproduction](../phase104/investigation.md) and [BUG-126](../../bugs/BUG-126.md).

## Objective and exact scope

Make calls between two live realms in one heap execute in the callee's realm
and carry the actual thrown value back to the caller. This is the first missing
prerequisite for p104 initial iframe contexts, not iframe implementation itself.
Keep the one-agent-per-tab and existing separate realm/global design.

Affected areas: `vm/function.c`, `vm/interpreter.c`, minimal shared VM declarations
if needed, and WS074 focused tests. Scope covers ordinary bytecode/native calls,
bytecode/native constructors, accessor/VM API paths, and reentrant calls back to
the originating realm. Preserve argument/result/this/new.target and closure
identity, exception identity and existing stack/depth/error unwinding. Existing
generator/async dispatch must retain its behavior; smoke-test its cross-realm
boundary without expanding Promise/generator feature coverage.

No child Window/Document API, lifetime ownership/GC redesign, URL loading,
navigation, document.write/open/close, modules, CSSOM, HAL or toolchain work.
Both realms remain explicitly owned and alive for these tests. Do not claim
that this fixes detached-frame lifetime or completes p104/p100.

## Design and finite procedure

1. Reproduce the saved 8-check baseline against current source.
2. Route foreign-realm calls/constructors through the callee realm while keeping
   the existing same-realm interpreter frame fast path. Reuse VM entry points;
   preserve existing recursion/depth bounds and unwind the foreign stack before
   continuing or catching in the caller.
3. Make every VM/native/interpreter boundary consistently transfer the actual
   exception and relevant throw metadata to the caller without overwriting the
   thrown object's realm or swallowing allocation/depth failures. Include native
   constructor and accessor paths; don't repair only one failing instruction.
4. Add bounded bidirectional/reentrant, closure, constructor/new.target, native
   throw and C-API assertions. Keep test assertions independent and identify
   which paths were tested; no mass test262 rerun unless failures justify it.
5. Check changed source against full standards; run plain/ASan builds, focused VM
   tests, DOM regressions and Acid2/Acid3 preservation checks for changed behavior.

### Concrete call-boundary design (2026-09-30)

Foreign bytecode call/construct instructions route through existing vm_call /
vm_construct into the callee's realm, retaining the same-realm frame fast path.
Native paths use a scoped helper that restores callee/new.target on normal and
error exits. A shared internal transfer helper moves the actual foreign exception
and throw-site metadata to the caller and clears the foreign pending throw.
Ordinary/native default intrinsic prototypes are translated for direct foreign
new.target functions when their prototype is primitive. This preserves the
planned constructor scope; it adds no Reflect API or new syntax support.

Baseline 8-check probe is retained unchanged. A separate host-realms test adds
bidirectional/reentrant, closure/this, ordinary/derived construction, explicit
new.target and default Object/Array/Error prototypes, accessor exceptions,
generator/async smoke, VM API exceptions/throw-site, native ENOMEM and bounded
stack-overflow recovery. Both realms remain explicitly alive. Full bound/Proxy
function semantics and arbitrary unsupported JS feature combinations are not
claimed as ECMAScript conformance; p100 remains a separate complete Acid3 gate.
Reference: [ECMAScript GetPrototypeFromConstructor](https://tc39.es/ecma262/multipage/ordinary-and-exotic-objects-behaviours.html#sec-getprototypefromconstructor).
