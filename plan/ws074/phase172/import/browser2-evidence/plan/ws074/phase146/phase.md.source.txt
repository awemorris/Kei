## Exact scope / design / criteria

Repair only the existing VM factories vm_object_create and vm_array_create in vm/object.c,
and js_builtin_array in js/builtin.c. The raw object/Array factory must protect an
incoming prototype before first VM allocation and its unpublished newborn cell through
shape initialization and Array length-key/property construction. The shared builtin
Array helper must protect each cell input and its unpublished new Array until every
indexed definition succeeds, including collection during array construction and later
property/shape allocation. Use ordinary vm_heap_add_root/remove_root with checked
registration and exact cleanup on success/ENOMEM; no prototype/value/root ownership
survives return, no new permanent root or collector threshold/config behavior. An atom
key is already owned by heap atom table; root shape is already owned by heap. Preserve
existing return conventions, output unchanged on failure and array/object semantics.
For js_builtin_array, count>0 with NULL values fails EINVAL before allocation; count/root
array sizing overflow fails before allocation. No broader VM API/allocator audit.

Add a focused native factory fixture: direct calls with stack scanning disabled and
ordinary near-threshold allocations, genuine prototype and cell inputs, actual collection
counter, exact object/Array prototype/length/elements identities, returned result lifetime
and no leaked temporary roots after explicit result release. Bounded empty and nonempty
arrays; cold-heap raw shape initialization and failure cleanup where feasible. Re-run the
unchanged p145 native reproducer: three actual GC shapes must become16/16 and ASan
leak0; this supplies prerequisite evidence but does not rewrite q557 or clear p145.
